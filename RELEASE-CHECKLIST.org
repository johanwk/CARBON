prerelease publication to obtain wider user feedback, reporting no failures in
current practical testing. Unchecked items are coverage gaps, not confirmed
defects or a claim that every combination must pass before community testing.

and date. Use backed-up/disposable songs. This checklist is not authorization
for an assistant to flash hardware or write songs.

* Recorded practical hardware evidence
:PROPERTIES:
:CUSTOM_ID: recorded-practical-hardware-evidence
:END:
The maintainer reports, on the development candidates leading to rc1:
editable menu overviews work well; track and scene overviews, grey read-only
text and the 12-row menu layout work; expanded Step Edit works; Arp Chord
range voicings are musically useful and the return to ordinary arp works far
better after its fix; the startup mini-sequencer fix works. The rc1 identity
change adds no musical behaviour. Hrm/Inv pitch results were checked by
recording into Bitwig (note names there read one octave lower: naming only).

Earlier acceptance covers Scn gates, glide over MIDI/CV, pitch-grid preview,
performance modes, snapshot/recall, note-delay triplets/persistence, older
songs, Hrm, Inv/Compact, Program Change, Euclidean/bar-relative timing and
song transfers up to 1.37. Coverage differs by feature; every synth, route,
boundary or option combination is not tested. Physical 16 PPQ measurement
remains unrecorded.

* Focused source review disposition
:PROPERTIES:
:CUSTOM_ID: focused-source-review-disposition
:END:
- Snapshot capture/recall runs in serialized RT control paths. Full song copy
  plus explicit transient controls; no voice lists or PRNG copy. Recording and
  panel song-I/O checked at request and apply. Releases use old routes before
  restore; pending sequence notes are cancelled, arp/live/output cleanup runs.
  CV queue is consumed before restoring pairing/calibration. Save retains the
  snapshot; accepted load/clear invalidate it. Song mode restarts its entry.
- Recall restores clock source using normal clock policy; external sync and
  finite output queues prevent any claim of seamless or lossless transitions.
- Clock-key recognizer intercepts before ordinary menu/edit dispatch; release
  order/repeated edge tests exist. Full physical button/Shift interactions
  remain representative hardware checks, not merely recognizer-test evidence.
- Rate/pitch queues apply at 384-tick boundaries, preserve CCi precedence, and
  cancel at documented boundaries. Per-track pitch references support
  multi-selection. Tests exercise production clock/engine/controller paths.
- Grid preview is read-only, at most 64 steps x 6 event slots for the selected
  main grid per refresh, with bounded six-note voicing work. No gate draws or
  control execution. Dirty cells suppress LCD writes, not preview calculation.
  Main-loop preview can observe changing RT state; it is not an atomic future
  playback snapshot. CPU time and stack high-water require hardware evidence.
- Glide snapshots ordinary delayed-note settings; arp reads persistent
  controls at attack. Queue preflight prevents partial glide attack groups;
  cleanup has congestion tests. Existing general output saturation behavior
  was not redesigned.

No reproducible new firmware defect was established in this focused pass. This
is not a complete historical source audit or proof of all interrupt
interleavings. The source has a longstanding panel-menu format-overflow
compiler warning; retain its exact diagnostic in build logs and assess
separately from measured failures.
