#+title: Built-in menu overviews and editing
#+options: ^:nil -:nil

* Open and navigate

Included in community 1.38-rc1. Hold Clock, Arp, MIDI or Tonality alone for
800 milliseconds to replace the main grid with that menu's overview.
Release leaves it open. Tap the same button (or Clock) to close. Motion Start
selects a row; Length/Value edits its value. Other encoders do nothing here.
Edits remain applied when the overview closes; closing is not Cancel/Undo.

Clock has21entries, Arp3, MIDI22 and Tonality14, in normal menu order. Up to
twelve rows are visible, with a > selection marker and highlighted value field.
The heading gives menu/track/scene/item count. A blank separator row and two
help lines follow the list. scn4 uses13pixel row spacing with the same font;
track/scene overviews retain their16pixel spacing.
As of scn3 the redundant =value line is removed; values remain in the list.
MIDI scene Program rows include A/B and scene number explicitly.

Unshifted short presses of Arp, MIDI and Tonality now act on RELEASE, after
ruling out a long hold. Arp still toggles enable on a short tap outside its
overview; holding Arp never toggles it. MIDI/Tonality taps open their normal
menus. Shift+Arp, Shift+MIDI (System) and Shift+Tonality (Swing) remain immediate
on press. Touching another control during a pending unshifted hold cancels
both that hold and its deferred tap, preventing unintended toggles.

Other button presses close an overview before retaining their normal action;
menu-button presses are deferred as above and can open a different overview.
Matching releases from earlier presses continue to reach their owner.
Clock-first Record/Load/Run shortcuts before the800ms threshold retain
capture/recall/undo priority and cancel help detection. Once a Clock hold
opens the overview it cannot become one of those actions until Clock has
been released and freshly pressed. Shift+Clock retains tap tempo outside an
open overview. Clock is always a close gesture inside an overview.

* Editing and safety

Overview editing and ordinary menus share the SAME per-item edit handlers;
there is no separate parameter implementation. Existing multitrack semantics,
validation, queued next-bar performance changes, CCi/Hrm precedence, cleanup
and song/session scopes apply. MIDI port/channel edits can release notes;
Program edits can send Program Changes. These are real edits, not previews.

Snapshot and Recall are the only informational Clock rows: Length/Value does
nothing there. They display Empty/Ready/Next bar as applicable, with status-only
help. Use the existing shortcuts or normal menu for those actions. Magic Range
and Chance edit their parameters only; they do not execute Magic.

The overview is not a track selector. To change tracks, close it or press a
track button (which exits before its normal selection action), then reopen.
While multiple tracks are selected, the first selected track supplies the
readout and normal controller multiselect rules apply to edits.

* Values and overrides

Values follow the same formatter as the normal menu and refresh as they change.
They are not a saved screenshot or a preview of future automation.

Clock Step Length can show effective CCi16 with a CCi marker. Queued manual
choices show >bar; >bar* additionally marks an active CCi override. Only when CCi16 is active, a detail
line labelled Edit shows the base/queued editing value, so editing does not
pretend to remove an override. Other entries retain normal-menu display rules:
Arp parameters show stored/queued values, and Tonality Scale shows effective
scale/root while edits target the stored base. Help warns when CCi/Hrm can
retain precedence. Pending Arp Speed/Transpose readouts follow normal menus.

Snapshot/Recall remain status-only. Humanize edits are still per-track session
preferences, not saved settings. Ordinary arp uses velocity/lateness only;
Chord is excluded. No storage/version migration or host-tool change is needed.

* Display and timing

Opening preserves the existing menu/editor and grid selection overlays.
Menu/editor inactivity countdowns pause while viewing; musical clock, note
cleanup and recording continue. Closing restores the grid without clearing
its selection. External scene/song changes can still update/end editing under
normal rules. Power changes close the view and reset hold recognizers.

Rendering uses a small cached text overlay in the normal GUI loop, not a
framebuffer or timer-interrupt LCD drawing. Only changed rows redraw. Hold
detection uses the existing1ms panel task without waiting or blocking playback.
Both LCD layouts retain their grid positions/font. Source helper names that
still mention clock_help now represent the shared overview display.

* Expanded Step Edit (local 1.38-jwk-edt2)

While already in Step Edit, hold Step Edit alone for 800 ms to toggle the
expanded display. Release leaves it active; hold again to return to compact.
The preference lasts for this firmware session, including leaving/re-entering
Step Edit. It is not stored in songs. Entry into Step Edit remains immediate;
a short unshifted tap within Step Edit now retriggers the preview on release.
The long hold itself does not audition notes, edit events or capture Undo.
Shift+Step Edit still opens Pattern Edit. Another control cancels a pending
hold/tap. Existing timeout, exit, selection and editing controls are unchanged.

Expanded mode replaces the six miniature track previews and their selection/
arp bars, not the main step grid or its pitch strokes. Seven rows show:

- Existing step title/context (including special control-event hints).
- Event types for all six slots.
- Note: stored note pitch, edited with Transpose. Control slots retain their
  normal first value instead; this is not a separate transpose offset.
- Vel: note velocity, edited with Length/Value. Control slots retain their
  normal second value instead.
- Gate: note gate duration. Non-Note slots show ---.
- Dly: per-note onset delay, edited with Speed when a slot is selected. Step
  means inherit the shared step delay; OFF is an explicit zero delay. Relative
  labels remain available. Non-Note slots show ---.
- Ratchet: whole-step ratchet setting (Pattern), followed by Step delay: the shared
  delay edited by Speed with all slots selected. Ratchets are not per note.

The selected event column is highlighted across the type/value rows. Motion
Start and Shift+Motion Start retain step/event selection. All five editing
dials retain their original semantics. Closing restores miniature previews.

Host tests cover mixed Note/Prb data, slot six, persistent simultaneous values,
inherit/Off delays, no toggle-time preview/data/Undo mutation, both LCD layouts,
preview suppression/cache updates, restoration, and hold/tap/cancel/Shift paths.
Physical readability, hold feel and busy-playback responsiveness remain untested.

User reports the expanded edt1 display works well on hardware. In edt2 the
label reads Ratchet, and turning Pattern in Step Edit no longer triggers a
misleading single-hit audition (compact and expanded views). Normal sequence
playback still plays ratchet repetitions; no repeated editor audition was added.
This follow-up awaits hardware confirmation.

* Track overview across scenes (local 1.38-jwk-trk1)

Hold a track button alone for800ms to open a read-only overview over the main
grid. Track selection happens immediately on press, as before; release leaves
the overview open. Tap Clock to close. All encoders are inactive. Other button
presses close the view and keep their normal action; holding another track can
then open its overview. Viewing the six scenes does not select/play them.

Fourteen rows show the track number and VOICE/DRUM, a column heading, then
two lines for each scene. The selected panel scene has a highlighted *number.

#+begin_example
TRACK 2 / VOICE / stored
SC RANGE RATE  BIAS MUTE
*1 01-16 1/16  -    Off
   C Major
 2 57~08 1/8   T1   On
   Song(C) Nat Minor
#+end_example

Scenes3..6 follow in the same view. RANGE is the inclusive1-based motion
start/end, not a playhead or playback direction. A tilde means the window wraps
through step64 to1. RATE is stored Step Length, including triplet/dotted and
bar-relative choices. BIAS shows T1..T6 or -; MUTE shows stored On/Off.
VOICE/DRUM is track-wide. Each scene's second line shows its root and this
track's stored scale. Song(C) means inheritance from song root C; Song(Off)
and explicit Root Off are distinguished. Roots are scene-wide, not per track.
Existing short scale names fit without truncation.

The view refreshes stored values but does not substitute live CCi/Hrm values
or pending next-bar targets. It makes no song edits, MIDI output or scene
requests. Normal track selection still has its existing side effects (including
ending recording); the long hold adds only the display. Menu/editor inactivity
timers pause while viewing, while playback/note cleanup continue normally.
Closing restores the grid and preserves the existing editor selection overlay.

Any other button or nonzero encoder cancels an uncompleted hold. No hold is
armed with another button down, Shift mute, Scene selection, Shift+Scene copy,
held multitrack selection, or Scn scene-mask editing. Power changes clear the
hold recognizer and close the overview. The trk1/trk2 view adds no scene-button overview or editing
controls; the complementary scn1 scene view is described below.

Host tests cover all tracks/scenes, both LCD layouts, all4096motion windows,
all scales/roots/inheritance, rate labels, live refresh/highlighting, read-only
encoder guards, caching/restoration and799/800ms/cancel/chord gesture paths.
Hardware legibility, gesture feel and busy-playback headroom remain unverified.

In local1.38-jwk-trk2, expanded Step Edit uses Note, Vel, Gate and Dly
in a five-character label field (including spacing). Event columns move two
characters right; the expanded display uses29characters instead of28 so the
sixth slot still shows all four characters, including Step and relative delays.
Compact Step Edit and ordinary menus retain their existing widths. Both-LCD
geometry, slot-six text/highlights and the existing host suites pass. The trk1
read-only track overview is retained unchanged; hardware checks remain pending.

* Scene overview across tracks (local 1.38-jwk-scn1)

Hold Scene FIRST, then press and hold a numbered button for800ms while keeping
Scene down. This is select-and-inspect: the numbered press immediately makes
the normal scene-change request (and ends recording as before). Scene Sync
still controls when playback changes. The hold only opens the read-only view;
it does not issue another request. A short Scene+number retains normal use.

The view stays pinned to the numbered scene, even while the engine is still
playing another scene or later changes scenes. It shows stored values, not
CCi/Hrm overrides or queued performance targets. Fourteen rows contain the
scene/root heading, column heading, then two lines for each of the six tracks:

#+begin_example
SCENE 3 / Song(C) / stored
TR RANGE RATE  BIAS MUTE
*1 01-16 1/16  -    Off
   VOICE Major
 2 57~08 1/8   T1   On
   DRUM  Chromatic
#+end_example

Tracks3..6 follow. Selected tracks have highlighted *numbers (multiple possible).
Ranges, wrap notation, rates, bias and mute mean the same as in track overview.
The shared scene root is in the heading, including Song(root) inheritance and
Root Off. Each second line shows that track's VOICE/DRUM and stored scale.

Release either/both buttons after opening to leave the view visible. Clock
closes; all encoders are inactive. Other button presses close then perform
normal actions. Releasing either chord button before800ms cancels the hold,
without cancelling the scene request already made. Another button/encoder
cancels detection; Shift+Scene+number copy and Scn mask editing retain priority.
Number-first then Scene does not open a scene overview. Holding Scene alone
has no new action. Power changes reset recognizers and close the view.

Host tests cover scenes/tracks, roots/scales, both LCD bounds, selected-track
highlights, pinned scene despite engine changes, read-only guards, cached live
refresh/restoration and chord threshold/cancel/release/exclusion paths. User
reported trk2 works really well; this scene extension awaits hardware checks.

In local1.38-jwk-scn2, read-only track and scene overviews use the existing
GUI grey (#999999) instead of normal bright white (#eeeeee). Selected track/
scene markers retain their inversion. Editable menu overviews and Step Edit
keep their existing colours. Switching between read-only and editable views
invalidates the row cache so identical text cannot retain the wrong colour.
Both-LCD renderer tests check these colours; physical contrast awaits review.

In local1.38-jwk-scn5, the redundant Start:row Length:value footer is removed.
Twelve parameter rows, blank separator, two help lines and the conditional
Clock CCi Edit detail remain unchanged, as do the encoder controls.

Local1.38-jwk-scn6 uses the removed footer space for a thirteenth parameter
row. The blank separator, two help lines and conditional Clock CCi Edit detail
still fit both LCDs at the same font size/13pixel spacing. Track/scene views
are unchanged.

Local1.38-jwk-scn7 fixes miniature track previews missing at startup until
Step Edit was entered. GUI initialization now clears its entire CCM-resident
state before applying defaults, including expanded-view/overview flags. A
nonzero-memory startup regression verifies first-frame drawing of all six
mini grids and selection/arp bars on both LCDs. Hardware confirmation pending.

Local1.38-jwk-scn8 restores12parameter rows and adds a blank line above the
menu heading for readability. The lower blank separator, help positions, font
and spacing remain unchanged. Track/scene layouts and scn7 startup fix remain.

* SYS overview (local 1.38-jwk-sys1)

Hold Shift FIRST, then hold MIDI for800ms with Shift still down. Short
Shift+MIDI keeps its immediate normal SYS-menu action; holding opens the
editable overview. Release leaves it open; Clock closes. Motion Start selects
a row and Length/Value edits, using the normal System handlers. Other encoders
are inactive. Twelve rows with top breathing room and help separator follow
the same layout as the other editable overviews.

All20System items are included: version/LCD, CV/Gate pairing, bend range,
four output modes, four scaling values, four span calibrations, four offsets
and menu timeout. Version is status-only and is not highlighted for editing.
CV Mode/Scaling rows include output numbers. Opening/scrolling does not edit
settings or calibrate outputs. Value edits are real: CV routing, scaling, span
and offset changes can affect connected hardware immediately. Use a meter
when calibrating. Timeout uses the existing global configuration preference.

Releasing either chord button before the threshold or using another control
cancels detection. MIDI-first then Shift is not a SYS hold. Existing plain
MIDI, Shift and power-reset paths remain. Both-LCD row/formatter/edit-dispatch
and799/800ms/release/cancel tests pass. Hardware gesture/output checks pending.
